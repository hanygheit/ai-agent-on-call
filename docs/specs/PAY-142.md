## Outcome
Merchant webhooks survive transient failures: a delivery that fails with a 5xx,
a timeout or a network error is retried; a 4xx is not.

## Non-goals
- No queue / persistence (separate ticket).
- No change to the public `sendPaymentWebhook()` signature.

## Constraints
- Follow [ADR 0007](../adr/0007-webhook-retry-policy.md).
- No new dependency. One source file + tests. ~50–80 lines.

## Approach
Wrap the single `fetch` in a retry loop: retry on 5xx, timeouts and network errors;
never on 4xx. Backoff 200 ms × 2 (200 → 400 → 800 ms). Max 4 attempts.
Inject `fetch` and `sleep` so tests are fast and deterministic.

## Files to touch
- `src/webhook-client.ts` — retry loop, per-attempt timeout, error type
- `test/webhook-client.test.ts` — unit tests

## Tests / acceptance
- [x] 503, 503, 200 → delivered on attempt 3
- [x] 400 → no retry, fails immediately
- [x] timeout then 200 → delivered on attempt 2
- [x] 4 × 500 → throws `WebhookDeliveryError` with last status and attempt count
- [x] backoff sequence is 200, 400, 800 ms

## Risk & rollback
Low blast radius (one call site, `grep` found no other callers). Rollback: revert the PR.
